# Performance Stage 2 — главная страница

## Итог

Stage 2 прошёл заданный порог:

- Main Thread: **1912 → 1015 мс** (**−46,9%**).
- LCP: **1128 → 692 мс** (**−38,7%**).
- Цель была не менее −20% Main Thread и −15% LCP.

Сравнивались чистый `main` (`177210d`) и ветка `performance/home-stage-2`, которая включает Stage 1.

## Методика

- 5 чередующихся cold-load запусков каждой ветки.
- Новый профиль Chrome для каждого запуска, cache disabled.
- Viewport: 1365×768.
- Окно измерения Main Thread: от navigation start до 5 секунд после `window.load`.
- Main Thread: `Performance.TaskDuration` из Chrome DevTools Protocol.
- Long Tasks: `PerformanceObserver`, задачи более 50 мс.
- В отчёте приведены медианы пяти запусков.

## Результаты

- Main Thread: 1912,4 → 1014,7 мс, **−46,9%**.
- Long Tasks: 2 → 2.
- Сумма Long Tasks: 221 → 220 мс.
- Самая длинная задача: 119 → 123 мс.
- DOMContentLoaded: 894 → 894 мс, без значимого изменения.
- `window.load`: 3261 → 935 мс, **−71,3%**.
- LCP: 1128 → 692 мс, **−38,7%**.
- GET всего: 153 → 125, **−18,3%**.
- GET `/auth/v1/*` на гостевом cold load: 0 → 0.
- GET `/rest/v1/profiles*` на гостевом cold load: 0 → 0.
- С синтетической авторизованной сессией: auth 11 → 4, profiles 11 → 4.

Long Tasks пока нестабильны: медианное количество и суммарное время не изменились, а самая длинная задача выросла на 4 мс. Это отдельная цель следующего этапа; общий Main Thread при этом уменьшился на 46,9%.

## Что изменено

### `index.html`

- Видео существующего загрузочного экрана перенесено в исходный HTML.
- Раньше `Fons/loading.mp4` создавался только из `loading.js` после разбора страницы.
- Теперь браузер обнаруживает и декодирует тот же ресурс сразу.
- LCP-элемент не изменился: это по-прежнему `.loading-video`.
- Обновлены cache-buster версий изменённых загрузочных скриптов.

### `scripts/boot-manager.js`

- Добавлен `ReminkoBoot.lateIdle(fn, delayMs)`.
- Он сохраняет стадию `Idle`, но даёт тяжёлым декоративным и аналитическим скриптам минимальную паузу после неё.

### `scripts/desktop-only-guard.js`

- GTM и Google Analytics сохранены.
- Их загрузка перенесена из раннего `requestIdleCallback` в `lateIdle`.
- Вызовы `dataLayer`/`gtag` продолжают ставиться в очередь до загрузки библиотек.

### `scripts/live2d-widget-init.js`

- Live2D по-прежнему запускается после исчезновения загрузочного экрана.
- Загрузка тяжёлой библиотеки и модели перенесена в `lateIdle`.
- Функции, модель и настройки виджета не менялись.

### `scripts/apply-navigation.js`

- Support Chat сохранён, но его скрипт загружается через `lateIdle`.
- Добавлена защита от повторной вставки скрипта.

### `scripts/navigation.js`

- Невидимые auth-модалки больше не создаются во время первого layout.
- Делегированные обработчики подключаются сразу, а DOM входа/регистрации создаётся при первом открытии.
- Добавлена защита от повторного подключения обработчиков.
- Аватары регистрации заполняются при ленивом создании модалки.
- LiveInternet и Яндекс.Метрика перенесены в `lateIdle`.
- Online widget и кэш ID создателя запускаются на `Idle`.

### `scripts/register.js`

- Удалён polling DOM каждые 100 мс в ожидании модалки.
- Аватары инициализируются по одноразовому событию ленивого создания auth-модалок.

### `scripts/home.js`

- Повторные события auth/favorites/history схлопываются в один refresh на кадр.
- Одновременные refresh ждут один общий Promise.
- Начальная история и избранное ждут лёгкие Kodik strips, чтобы не провоцировать раннюю загрузку полного каталога.
- Удалён второй безусловный idle-refresh тех же Hero-блоков.
- Одинаковое содержимое не перестраивается повторно благодаря render key.
- Карточки истории и избранного добавляются одним `DocumentFragment`.

## Проверки

- Синтаксис всех изменённых JS: успешно.
- IDE diagnostics: ошибок нет.
- Desktop smoke: Hero, 67 Kodik-карточек, уведомления, auth-модалки — успешно.
- Lazy auth: до клика модалок нет; после клика вход и регистрация открываются, 10 аватаров доступны.
- Mobile 375 px: горизонтального переполнения нет, модалка помещается в viewport.
- Dark theme: модалка использует тёмный фон, белых разрывов не найдено.
- Через 11 секунд подтверждены загрузка GTM, gtag, Яндекс.Метрики, Support Chat и Live2D.
- Доступны auth, registration, OAuth, notifications, friends, messages, history и favorites API.
- Необработанных JavaScript exceptions (`pageerror`) нет.

Локальный сервер показывает сетевые ошибки Shikimori CORS и один внешний 504. Это ограничение локального origin: на production Shikimori настроен через Netlify proxy. Эти сообщения существовали в baseline и не вызваны Stage 2.

## Риски и ограничения

- GTM/gtag/Яндекс.Метрика запускаются позже. Очередь событий сохраняется, но очень короткий визит до позднего запуска может не попасть в стороннюю аналитику.
- Live2D и Support Chat появляются позже, зато не блокируют первые секунды взаимодействия.
- Auth-модалка создаётся при первом клике; smoke-тест не обнаружил заметной задержки.
- Измеренный LCP относится к видео загрузочного экрана, а не к Hero. Раннее обнаружение видео честно улучшает текущий LCP, но content-LCP после снятия оверлея нужно отдельно измерять через production RUM.
- Реальные вход, регистрация и OAuth не выполнялись без тестового аккаунта; проверены обработчики, синтетическая Supabase-сессия и отсутствие runtime exceptions.

## Что осталось

- Разбить initial layout главных лент, чтобы стабильно убрать вторую Long Task.
- Добавить отдельную метрику времени появления Hero после снятия loader.
- Проверить production RUM на мобильных устройствах и медленной сети.
- После подтверждения RUM решить, оставлять ли поздний запуск аналитики на текущей задержке.
